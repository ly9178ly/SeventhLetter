# 第一阶段开发与验收记录

日期：2026-11-14。版本：0.1（第一章可玩开发版）。

这是第一阶段历史记录。第二至第四章、推理与四结局的当前实现和验证见[第二阶段验收记录](第二阶段验收记录.md)。

## 已实现

4 个原生页面：主页、调查、证据档案、调查记录；11 个剧情节点、4 项证据、条件选项、可复查路径、自动保存、手动保存、新调查确认。

业务规则与 UI 分离。每次选择先检查条件，再生成新状态；Preferences 成功 flush 后 UI 才进入下一节点。保存失败保留原节点，允许重试。证据和 flags 去重，选择历史最多保留 200 条。

存档校验包括 JSON、版本、节点、证据 ID、flags、历史条目、大小限制。读取失败或坏档不自动覆写；重新开始必须确认。

## 实际环境

Windows 11 x64；DevEco Studio 5.0.5 Release（5.0.13.240）；HarmonyOS API 17；Huawei_Phone x86_64 模拟器（镜像 5.0.1.121 SP1）。使用 DevEco 自带 Node、JBR、Hvigor 构建，没有修改全局 PATH 或 Codex/DeepSeek Harness 配置。

本机模拟器实际接受 `entry-default-unsigned.hap`，并成功启动应用。物理设备和其他模拟器的签名要求需分别检查，不保证同一未签名包直接通用。

## 发现与处理

- ArkTS 不支持 TypeScript 的构造器参数属性：改成显式字段和构造器赋值；重新编译通过。
- ArkTS 不允许直接抛出未确定类型的 catch 值：转换为明确的 Error。
- 首轮自动化脚本错误读取 Text 子节点的 enabled 属性：改为检查实际父 Button，并真实点击锁定选项验证不能跳转。
- 冷启动测试捕获过系统 `LIFECYCLE_TIMEOUT`，后续录屏准备时再次出现，并伴随 `render_service` 冻结和模拟器自动恢复。线程栈停在系统渲染服务的 `CreateNodeAndSurface` IPC，尚未进入应用页面加载。测试脚本留出 1 秒进程退出间隔，但证据不支持宣布渲染问题已修复；这是本机模拟器的已知待观察问题。成功完成的恢复测试与该问题分别记录，不将单次通过当作稳定性保证。
- Windows 模拟器可通过完整路径启动并被 HDC 识别；未继续盲目重装 WMIC，也未修改系统环境变量。
