# 上手与修改指南（四章故事 0.2）

## 现在怎么玩

在 DevEco Studio 打开工程根目录，启动 API 17 Phone 模拟器，选择 entry/default 运行。首页点击“开始新的调查”。

推荐第一遍自由探索。无法点击的选项下面会显示缺少什么；点击底部“证据档案”能重读信件。每个成功选择自动保存；“保存”可以再次主动保存。

应用关闭后重新打开，点“继续调查”恢复上次位置。“开始新的调查”会明确提示覆盖调查进度，目前只有一个存档槽；已解锁结局会保留。0.1 版存档可以继续，原来的第一章结束处已经接上第二章。

第一章到“第七个收件人”后，跟随沈予进入第二章。在档案室查看维修夹、合影/清场单和事故卷宗，点击“证据推理”核对身份和被困原因，再与沈予对质。第三章收齐六封信，完成声音记录的核对，第四章查看根据证据生成的第七封信并作出决定。

推理方法：选两份已取得材料，再选一个判断，点“核对并保存”。选错不扣分、不锁死；点击“先读证据全文”可回看。第三项推理所需材料在第三章获得。

最终选择有确认页面。主结局需要三项核对和六封信；其他结局由明确的主动选择产生。到达结局后可返回最终抉择前补查，图鉴只收录实际体验过的结尾。回看图鉴正文不会改变当前进度。

## 用本机脚本运行

在工程目录打开 PowerShell，命令如下（安装位置不同请替换路径）：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1 -Task Build -DevEcoHome 'D:\huawei\DevEco Studio'
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1 -Task Test -DevEcoHome 'D:\huawei\DevEco Studio'
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1 -Task Run -DevEcoHome 'D:\huawei\DevEco Studio'
```

Run 前启动模拟器，并保持仅连接一个目标设备。脚本借用 DevEco 的 Node/JBR，执行后恢复当前进程的环境设置。若 PowerShell 命令不在 PATH，可用系统 PowerShell 的完整路径，或直接从 DevEco Terminal 运行；不要为此随意改全局 PATH。

老师电脑需先由 DevEco 完成工程同步/依赖恢复。物理设备按 IDE 提示配置其本机签名，不能复用他人的私钥。

## 怎么修改

| 想改什么 | 文件 | 注意事项 |
| --- | --- | --- |
| 情节、对话、选项 | `data/ChapterOne.ets`、`data/LaterChapters.ets` | 保持既有 id 稳定；target 必须指向有效节点 |
| 信件全文 | 上述文件中的 `EVIDENCE` / `LATER_EVIDENCE` | 不改已有证据 id；新增线索同步测试 |
| 推理问题、证据组合与正确判断 | `data/StoryData.ets` 的 `DEDUCTIONS` | 证据必须已取得，严格匹配两项；不能只凭选项文字解锁 |
| 第七封信草稿 | `engine/StoryEngine.ets` 的 `letterDraft` | 根据核对结果生成，区分事实与未知 |
| 解锁规则 | Choice 的 requires / requiresFlags | 分别需要证据和故事标记；grants/sets 表示选择后的收获 |
| 背景、纸色、文字颜色 | `components/Theme.ets` | 检查对比度与锁定状态可读性 |
| 主页 | `pages/Index.ets` | 新调查会覆盖存档，保留确认流程 |
| 剧情排版、选择按钮 | `pages/Investigation.ets` | 保留保存成功后再更新页面的顺序 |
| 存档规则 | `storage/SaveRepository.ets` | 改 schema 必须考虑迁移，不能假装旧档兼容 |
| 真实设备存储 | `storage/PreferencesPort.ets` | 使用 Preferences 并 flush，不能仅存在内存 |

建议第一次只改一段正文：保存 → 运行 Build → 模拟器打开对应节点 → 对比实际显示。改分支条件时同时补 `src/test/Story.test.ets` 中的正常、锁定和异常用例，再运行 Test。

## 如何复验

- 本地单元测试：上面的 `-Task Test`；报告生成于 `entry/.test/default/outputs/test/reports/`。
- 宿主 Mock 测试：`node scripts/test-host.cjs '<DevEco目录>/tools/ohpm/node_modules/typescript'`。
- 完整故事原生测试：`python scripts/smoke-story.py --hdc '<SDK目录>/default/openharmony/toolchains/hdc.exe'`，需要 Pillow 和本机开发模拟器的存档文件访问权限。会先备份再恢复原存档，覆盖安装的读档、四结局与图鉴都会验证。
- `smoke-emulator.py` 保留第一章的界面检查，`--record` 连续采样到 `docs/demo.gif`；这份旧脚本会重开并覆盖进度，日常试玩无需运行。

完整故事脚本仅操作此应用的一个存档文件，备份留在 `artifacts/story-smoke/preference-before.xml`（不提交 GitHub）。测试异常中断或电脑断电时，应先保留备份并恢复，不要直接重跑覆盖它。普通用户直接玩应用即可，无需测试脚本。
